# table-etl

[![tests](https://github.com/basovdanil/table-etl/actions/workflows/tests.yml/badge.svg)](https://github.com/basovdanil/table-etl/actions/workflows/tests.yml)

Три операции, которые регулярно нужны перед загрузкой табличных выгрузок в базу:
слить несколько файлов, сравнить две версии и разложить таблицу по значению колонки.

Только стандартная библиотека Python 3.8+. Формат входа — CSV, который отдаёт
Excel и 1С: разделитель `;` или `,`, UTF-8 или windows-1251 с BOM.

## Пайплайн

```text
v1.csv + v2.csv ──▶ merge ──▶ одна таблица, дубли по ключу схлопнуты последней строкой
v1.csv + v2.csv ──▶ diff  ──▶ v2.csv (только добавленные) + report.json (added/removed/changed)
v2.csv          ──▶ split ──▶ parts/part-01.csv … + parts/manifest.json
```

## Команды

| Команда | Что делает |
| --- | --- |
| `merge` | сливает файлы по ключу, объединяет набор колонок, дубли отбрасывает |
| `diff` | сравнивает две версии таблицы и пишет строки `добавлено` / `удалено` / `изменено` |
| `split` | раскладывает таблицу на файлы по значению одной колонки и пишет `manifest.json` |

При слиянии дубль по ключу заменяется последней встреченной строкой: свежий файл
побеждает старый. Колонки, которых нет в первом файле, добавляются в конец, а в
ранних строках остаются пустыми.

При сравнении в выходном CSV две служебные колонки: `_change` и `_columns` —
во второй перечислены поля, которые изменились. Машиночитаемый вариант отдаёт
`--json`: `added`, `removed`, `changed` и `changed_columns` со списком полей по ключу.

## Запуск

```
python etl.py merge --inputs reg-01.csv reg-02.csv --key id --out old.csv
python etl.py diff --old old.csv --new new.csv --key id --out diff.csv
python etl.py split --input new.csv --by склад --outdir parts
```

Флаг `--json` у любой команды: объект в stdout, без цвета и прогресса, годится
для вставки в пайплайн.

## Демо

В `demo/` три выгрузки регистра на 72 строки, синтетические: вымышленные
контрагенты, склады и суммы.

```
python etl.py merge --inputs demo/reg-01.csv demo/reg-02.csv --key id --out work/old.csv
# rows_in=51 rows_out=45 duplicates=6

python etl.py merge --inputs demo/reg-01.csv demo/reg-02.csv demo/reg-03.csv --key id --out work/new.csv
# rows_in=72 rows_out=60 duplicates=12

python etl.py diff --old work/old.csv --new work/new.csv --key id --out work/diff.csv
# rows_old=45 rows_new=60 added=15 removed=0 changed=0

python etl.py split --input work/new.csv --by склад --outdir work/parts
# parts=3 rows=60
```

В демо третья выгрузка только добавляет строки, поэтому дифф показывает 15
добавлений без изменений и удалений. Изменённые и удалённые строки проверяются
тестами на отдельных фикстурах.

## Коды возврата

| Код | Значение |
| --- | --- |
| `0` | готово |
| `2` | неверные аргументы |
| `3` | файла нет |
| `4` | ошибка данных: нет колонки ключа или пустой ключ |

## Тесты

```
python -m unittest discover -s tests
```

11 тестов: объединение колонок, замена дубля последней строкой, пустой ключ,
отсутствующая колонка, все три вида изменений в диффе, список изменившихся полей,
разбивка с `manifest.json`, коды возврата и разбор `--json`.

## Данные

Все файлы в `demo/` синтетические. Совпадения с реальными контрагентами, суммами
и складами случайны.

## Границы

Скрипт работает со строками как с текстом и не приводит типы: `10.0` и `10`
считаются разными значениями, а сортировка чисел выполняется после загрузки в
базу. Разбор колонок с многострочными значениями и разделителем `;` требует,
чтобы CSV был корректным: эвристику на «похоже на число» скрипт не делает.
